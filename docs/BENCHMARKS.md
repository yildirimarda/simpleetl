# SimpleETL Benchmark Results — Pandas-Only Baseline

## Methodology

- **Baseline:** `pandas` engine (`engine="pandas"`) explicitly set for all format I/O and transformations. No `polars` fast path is used.
- **Dataset:** Synthetic 1,000,000-row DataFrames generated by the benchmark scripts (`generate_test_data`).
  - Read/write: 6 columns (`id`, `name`, `age`, `score`, `active`, `city`).
  - Transformations / streaming: 7 columns (`id`, `name`, `age`, `score`, `active`, `city`, `signup_date`).
- **Runs:** Default benchmark settings:
  - Read/write: 5 runs (median reported).
  - Transformations: 5 runs (median reported).
  - Streaming: single measurement with `tracemalloc`.
- **Environment:** Linux aarch64, Python 3.11 (via `uv`), SimpleETL v0.3.0, `pandas>=2.0.0`, `pyarrow>=12.0.0`.
- **Reproduce:**
  ```bash
  uv run python -m benchmarks.benchmark_read_write
  uv run python -m benchmarks.benchmark_transformations
  uv run python -m benchmarks.benchmark_streaming
  ```

## Read / Write Performance (1,000,000 rows, 6 columns)

| Format  | Mean (s) | Median (s) | Min (s) | Max (s) |
|---------|----------|------------|---------|---------|
| CSV     | 0.940    | 0.943      | 0.925   | 0.953   |
| JSON    | 0.937    | 0.939      | 0.928   | 0.947   |
| Parquet | 0.935    | 0.934      | 0.929   | 0.943   |

**Observations:** All three formats complete a full write+read round-trip in ~0.94 s on 1 M rows. Parquet is marginally faster and more consistent; CSV and JSON are nearly identical.

Median of 5 runs. All operations use the default `pandas` engine.

| filter (column, min/max)   | 0.0213   | 0.0199     |

| union                      | 0.0013   | 0.0012     |
| window (rank)              | 0.0079   | 0.0078     |
| window (lag+cumsum)        | 0.0057   | 0.0057     |
| string (lower)             | 0.0006   | 0.0006     |
| string (replace)           | 0.0016   | 0.0016     |
| string (contains)          | 0.0026   | 0.0026     |
| string (length)            | 0.0005   | 0.0005     |
| date (extract year)        | 0.0008   | 0.0008     |
| date (trunc month)         | 0.0032   | 0.0032     |
| date (format)              | 0.0075   | 0.0074     |
| date (is_weekend)          | 0.0013   | 0.0012     |
| chain (4 steps)            | 0.0621   | 0.0610     |
| chain (9 steps)            | 0.0932   | 0.0920     |

**Observations:**
- All transformations scale roughly linearly with dataset size.
- `map (callable)` is the slowest (~94 ms) due to per-row Python function calls.
- `union` is fastest (~1.2 ms) — a simple `pd.concat`.
- Window functions are consistent regardless of dataset size because they operate on partitions.
- String operations are very fast due to vectorized `.str` accessor.
- Chain overhead is minimal: 9 steps on 1 M rows completes in ~92 ms.

## Streaming / Chunked Performance (1,000,000 rows, chunk_size=10,000)

| Format | Non-Chunked (s) | Non-Chunked Mem (MB) | Chunked (s) | Chunked Mem (MB) |
|--------|-----------------|----------------------|-------------|------------------|
| CSV    | 11.386          | 136.3                | 11.747      | 50.2             |
| JSON   | 15.492          | 1369.4               | 13.466      | 45.8             |
| Parquet| 0.181           | 12.4                 | 0.339       | 0.7              |

**Observations:**
- **Parquet** remains the clear winner: ~0.18 s non-chunked, ~0.34 s chunked, with very low memory footprint.
- **JSON** has the highest memory usage (~1.37 GB non-chunked); chunked mode reduces memory by ~97% with a slight speed improvement.
- **CSV** chunked mode reduces memory by ~63% at the cost of ~3% more time.
- For memory-constrained environments, chunked mode is essential for JSON processing.

## DAG Microbenchmarks

DAG benchmarks measure topological sort, parallel groups, validation, and construction. They are independent of dataset size and remain sub-millisecond for 100-node graphs.

## Conclusion

The pandas-only baseline on 1 M-row synthetic datasets demonstrates that the framework completes full read/write, transformation, and streaming pipelines in under a second (parquet/I/O) to ~15 s (JSON streaming, non-chunked). All results were produced with `engine="pandas"` to establish a reproducible baseline before comparing against optional backends such as `polars`.
